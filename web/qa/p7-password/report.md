## რეალური Neon Auth

Fixture-ის გარეშე dev სერვერის ხელახლა გაშვების შემდეგ, `DEMO-ACCOUNTS.local.md`-ის ერთი demo კლიენტი (სასტუმრო) გამოიყენებოდა. Ledger-ში QA/დროებითი ცალკე ანგარიში არ აღმოჩნდა. პაროლი პროგრამულად წაიკითხა სკრიპტმა და არსად დაბეჭდილა. შესვლა შესრულდა ერთხელ; 429 არ ყოფილა და მეორე შესვლა არ შესრულებულა. state დაცულია `/tmp/p7-password-client.json`-ში, რეჟიმი 0600 (არ არის git-ში).

| მოქმედება | Auth endpoint | HTTP | პასუხი / შედეგი |
|---|---|---|---|
| UI შესვლა ერთხელ | `/neondb/auth/sign-in/email` | 200 | წარმატებული |
| მიმდინარე = ახალი = ledger-ის არსებული პაროლი | `/neondb/auth/change-password` | 200 | toast „პაროლი შეიცვალა.“; სამივე ველი ცარიელია |
| არასწორი მიმდინარე პაროლი | `/neondb/auth/change-password` | 400 | `{"code":"INVALID_PASSWORD","message":"Invalid password"}` |

წარმატების შემდეგ ჰედერში ავტორიზებული მომხმარებელი დარჩა; პროფილის გვერდის refresh-ის შემდეგაც ავტორიზებულია. არასწორი პაროლის პასუხზე `password-current-error` შეიცავს „მიმდინარე პაროლი არასწორია.“ და ფოკუსი `password-current`-ზეა. pageerror 0; overflow 0. შედეგები: `live-results.json`. სურათები: `shots/live-success-1440.png`, `shots/live-invalid-1440.png`.

რეალური სიგრძის შეცდომები ხელოვნურად არ გამოწვეულა: მათ fixture ამოწმებს, რადგან UI შესაბამის მოთხოვნებს ქსელამდე აჩერებს. რეალური პაროლის მნიშვნელობა არ შეცვლილა. `revokeOtherSessions: true` არსებული მოთხოვნის პარამეტრია და შენარჩუნებულია.
