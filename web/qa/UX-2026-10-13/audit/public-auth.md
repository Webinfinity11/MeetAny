## რა ვერ შემოწმდა და რატომ

- ნამდვილი რეგისტრაციის დასრულება, ელფოსტის დადასტურება და აღდგენის წერილის მიღება: მოთხოვნის შესაბამისად რეგისტრაცია ვალიდაციამდე მივიდა; არ გაიგზავნა რეალური წერილი.
- ნამდვილ დოკუმენტებზე upload → pending → ადმინისტრატორის review: `owner_company`-ს დოკუმენტები არ ჰქონდა; ფიქციური დოკუმენტი განსახილველად არ გაიგზავნა. შემოწმდა ფორმატის უარყოფა და ცარიელი განხილვის submit. Pending-ის დრო/ტექსტი არ არის დადასტურებული. საინფორმაციო გვერდზე წერია 1–2 სამუშაო დღე.
- Onboarding „დასრულება“-ს საბოლოო mutation და პროდუქტის დუბლიკატების გამოსწორება: არსებული ჩანაწერები არ წაიშალა/გადაირქვა. Review-ის აქტიური ღილაკი არ ნიშნავს, რომ server საბოლოო submit-ს მიიღებს.
- უცვლელი **ვალიდური details** submit: საწყისი details არასრულია; მონაცემების ხელოვნურად შევსება არ შესრულებულა. Profile-ის შენახვა და არსებული type-ით წინ გადასვლა შემოწმებულია.
- სერვერის ხელოვნური outage/retry და ხანგრძლივი offline მდგომარეობა არ ინიცირებულა; ბუნებრივი სერვერული შეცდომა იზოლირებულ შემოწმებებში არ დაფიქსირებულა. შესაბამისად შეცდომიდან აღდგენა/ტოსტების სრული კატალოგი არ არის შეფასებული.
- რეალური iOS/Android კლავიატურის მიერ submit-ის დაფარვა: 390×844 desktop Chrome viewport რეალურ ვირტუალურ კლავიატურას არ ქმნის. Sticky ზოლები გადაღებულია, კლავიატურასთან ქცევა დასამოწმებელია.
- ThreadRig browser-ით სტუმრის/owner ფორმის შენახვის სრული გამეორება: საერთო cookie/localStorage სივრცე პარალელურ admin აუდიტს ეკუთვნოდა; მისი სესია არ შეიცვალა. როლები, შენახვა, ვალიდაცია და logout დამოწმებულია იზოლირებული Playwright-ით.

- QA სკრიპტების რამდენიმე პირველი გაშვება შეწყდა არმყოფი კონტროლის/არასწორი selector-ის timeout-ით (კომპანიის guest save, mobile profile-menu). ეს პროდუქტის ჩავარდნებად არ დათვლილა; შესაბამისი მოქმედებები დაზუსტდა და ცალკე ხელახლა შემოწმდა, გარდა პირდაპირ ჩამოთვლილი შეზღუდვებისა. Build არ გაშვებულა — შეიცვალა მხოლოდ აუდიტის დოკუმენტი.

## შექმნილი ლოკალური ჩანაწერები

ახალი ანგარიში, მოთხოვნა, შეთავაზება, გარიგება, შეტყობინება ან ატვირთვა **არ შექმნილა**. Owner-ის `account_intent` დროებით შეიცვალა `buy → both → buy`; `about`-ს დროებით დაემატა `[ux-audit]` და შემდეგ ზუსტად აღდგა თავდაპირველი ტექსტი. ორივე აღდგენა reload-ით შემოწმდა (`restored-about=true`, `restored-intent=true`). `[ux-unsaved]` და `[ux-unsaved-mobile]` მხოლოდ დაუშენახავი ფორმის ტესტები იყო; ხელახლა გახსნისას საწყისი აღწერა დადასტურდა. `.txt` ატვირთვა უარყოფილია და ბაზის/საცავის ჩანაწერი არ შექმნილა. სესიისა და ჩვეულებრივი აქტივობის ტექნიკური ლოგები შესაძლოა ავტორიზაციამ/გვერდების გახსნამ განაახლა.
