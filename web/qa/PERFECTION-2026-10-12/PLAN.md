# სრულყოფილება — გეგმა (2026-10-12)

მფლობელის მოთხოვნა: „ასეთი ხარვეზები არ უნდა იყოს“ — ვიზუალური შეუსაბამობა, ზედმეტი და გაუმართავი ტექსტი, ადმინში ყველაფერი სწორად უნდა იმართებოდეს. დამატებით: მთავარი გვერდი უფრო ინფორმაციული და დახვეწილი; ტელეფონზე (390/360) გადასვლები და UX დეტალები ესთეტიკური.

ანალიზი (ეტაპი 1) ხუთ ფართობზე, თითო ეკრანი 1440 და 390: `analysis/public.md` (32 ხარვეზი), `analysis/client.md` (54), `analysis/company.md` (31), `analysis/deal.md` (27), `analysis/admin.md` (იხ. §4). კადრები `before/<area>/`, სკრიპტები `scripts/<area>.mjs`. ჯამში ~150 ჩანაწერი; ბევრი ერთი და იმავე მიზეზის გამოვლინებაა, ამიტომ გეგმა მიზეზებით არის დაჯგუფებული, არა ეკრანებით.

## 1. სტანდარტი — როგორი უნდა იყოს

ყველა ნაკადი ამ წესებით მუშაობს. წესი, რომელიც კოდში უკვე არსებობს (DESIGN-SYSTEM.md, `ui/`), აქ მხოლოდ დაზუსტებულია.

### 1.1 ღილაკები და მოქმედებები
- მხოლოდ `ui/Button` (`variant`, `size`); საკუთარი ღილაკის CSS არცერთ კომპონენტში არ რჩება (მაგ. ყოფილი `SaveRequestButton.module.css`).
- ერთ ეკრანზე ერთი primary. მეორეხარისხოვანი მოქმედებები ერთ რიგში, ერთი ვარიანტით (`secondary` ან `ghost`), ერთი ზომით, ერთი გასწორებით. ერთ ჯგუფში ორი სხვადასხვა სტილი არ არის.
- წარწერა = ზმნა ან ზმნური სახელი, რომელიც ამბობს რა მოხდება: „მოთხოვნის განთავსება“, „შეთავაზების გაგზავნა“, „პროფილის ნახვა“, „ყველა მოთხოვნა“. შიშველი არსებითი სახელი („მოთხოვნა“, „შეთავაზება“, „პროფილი“, „გარიგება“) ღილაკზე არ იწერება.
- საშიში მოქმედება: `danger` + `ConfirmSheet`, სადაც primary იმეორებს მოქმედებას („გარიგების გაუქმება“), secondary არის „დაბრუნება“ — არასდროს ორაზროვანი „გაუქმება“.
- ტექსტური ბმული მხოლოდ მესამეხარისხოვანი მოქმედებისთვის („დარღვევის შეტყობინება“) და ერთი სტილით ყველგან (`ReportButton` ერთი რეჟიმით).
- შეხების სამიზნე ≥44px; ხატულების ერთი ოჯახი (`/icons.svg`).

### 1.2 ბარათები და სიები
- ბადეში ბარათები ერთი სიმაღლისაა (`grid-auto-rows: 1fr`, შიგთავსი ქვედა/ზედა კიდეზე ერთნაირად); ობოლი უჯრა არ რჩება — სვეტების რაოდენობა ელემენტების რაოდენობას ერგება (`auto-fit`, 5 → 5 ან 3+2, არა 4+1).
- ფოტოს ადგილას ცარიელი ნაცრისფერი ყუთი არ არის: კომპანიას — `Avatar` (ლოგო ან ინიციალები ბრენდის ტონით), მოთხოვნას — კატეგორიის ილუსტრაცია (`RequestCatalogCover`), სერვისს ფოტოს გარეშე — ჩიპი, არა ბარათი.
- ერთი ინფორმაცია ერთხელ: ბარათზე/გვერდზე იგივე ფაქტი ორ ადგილას არ მეორდება (ვადა ≠ „მიღება სრულდება N დღეში“ + „ბოლო ვადა“; სპეციფიკაცია არ იმეორებს ფაქტებს; სახელი არ მეორდება ქვესათაურში).
- სტატისტიკის ბარათი: რიცხვი + წარწერა ≤2 სიტყვა, ერთი სიმაღლე, რიცხვი და წარწერა ერთ ბლოკად. „0“ ყოველთვის წარწერით, არასდროს მარტო.
- ინიციალები ყველგან ერთი ფუნქციით (`avatarInitials`): ორი ასო, მხედრულით, ბრჭყალების/იურიდიული ფორმის გარეშე.

### 1.3 ცარიელი და შეცდომის მდგომარეობები
- ცარიელი სია = `ui/EmptyState` (ხატულა + ერთი წინადადება + ერთი CTA), აუდიტორიის ენით (გამყიდველს — გამყიდველის ტექსტი, მყიდველს — მყიდველის).
- არასავალდებულო ცარიელი სექცია (ფაილები, დამატებითი პირობები, განახლებები) არ ჩანს ცარიელ ბარათად: ან იმალება, ან ერთი ხაზია „… არ არის დამატებული“.
- ჩატვირთვის შეცდომა ერთი სტილით (`ui/Notice tone="error"` + „ხელახლა ცდა“); სტუმარს არასავალდებულო მონაცემის შეცდომა საერთოდ არ უჩანს.
- „შენახულია“ მხოლოდ მაშინ, როცა სერვერზე ნამდვილად შეინახა; ლოკალური ასლი — „შენახულია ამ ბრაუზერში“.
- 0-იანი მთვლელი ბეიჯად არ ჩანს (მენიუს „0“, ფილტრის „0“).

### 1.4 ტექსტი
- მიმართვა — **თქვენობითი ყველგან**: სათაურები, ღილაკები, შეცდომები, placeholder-ები, ტოსტები, წესები. („რა სჭირდება თქვენს ბიზნესს?“, „დაწერეთ შეტყობინება…“, „სცადეთ ხელახლა“.)
- ერთი ცნება — ერთი სიტყვა, ლექსიკონი:

  | ცნება | სიტყვა | არა |
  |---|---|---|
  | request | მოთხოვნა (სტუმრისთვის სია: „ღია მოთხოვნები“) | შესაძლებლობა, განცხადება |
  | offer | შეთავაზება | წინადადება |
  | deal | გარიგება | — |
  | supplier | მომწოდებელი (ორგანიზაციად — კომპანია) | გამყიდველი |
  | buyer | მყიდველი (ანგარიშის როლი — კლიენტი) | მომხმარებელი |
  | messages | მიმოწერები (ერთი: საუბარი; შიგნით: შეტყობინება) | მესიჯები, ჩატი (როგორც სექცია) |
  | notifications | შეტყობინებები | — |
  | saved | შენახული | — |
  | settings/profile tab | პარამეტრები | პროფილის პარამეტრები, ანგარიშის პარამეტრები |
  | verification | ვერიფიკაცია; სტატუსები: დადასტურებული / განიხილება / არ გაგზავნილა | დამტკიცება |
  | logout | გასვლა | ანგარიშიდან გასვლა |
  | cover | ფონური ფოტო | ქავერი |
  | card | ბარათი | ქარდი |

- სტატუსების ლექსიკონი (ერთი ფუნქცია, ყველა ეკრანი):
  - გარიგება (`dealStageLabel`): selected „მომწოდებელი არჩეულია“ · discuss „დეტალების განხილვა“ · terms „პირობების დადასტურება“ · progress „შესრულება მიმდინარეობს“ · complete „დასრულებული“ · cancelled „გაუქმებული“. მოვლენების სახელები (`dealActionLabel`) მხოლოდ timeline-ში.
  - შეთავაზება (`offerStatusLabel`): pending „მოლოდინში“ · viewed „ნანახია“ · selected „არჩეული“ · not_selected „არ შეირჩა“.
  - მოთხოვნა: ღია · იწურება · მომწოდებელი არჩეულია · დახურული · მონახაზი.
- ფორმატები: ფული `money()` → „1 920 ₾“ (დაჯგუფება ჰარით, ₾ ბოლოს; null → „შეთანხმებით“); თარიღი `dateShort()` → „8 ოქტ. 2026“, `dateLong()` → „8 ოქტომბერი 2026“, დრო `dateTime()` → „8 ოქტ. 2026, 14:08“. `toLocaleDateString()` ლოკალის გარეშე არსად.
- ბრუნვა საკუთარი სახელის შემდეგ დეფისით არ იწერება („ხის ხაზი-ს“ ✗) — წინადადება ისე იწყობა, რომ სახელი სახელობითში დარჩეს („კომპანიას „ხის ხაზი“ გაეზიარება…“).
- არ იწერება: placeholder („მფლობელი დაამატებს“), ტექნიკური შენიშვნა („სადემო პროდუქტი“), ჟარგონი, ტავტოლოგია, ცარიელი მნიშვნელობა („ძალაშია —“, „მიწოდების ვადა: არ არის მითითებული“ → ველი იმალება).
- შეცდომის ტექსტი ამბობს რა გასაკეთებელია, არ იმეორებს ეტიკეტს: „აირჩიეთ მიწოდების ვადა“, არა „მიუთითეთ 0–365 დღე“.
- ყოველ გვერდს საკუთარი `<title>` აქვს (კომპანიის სახელი, მოთხოვნის სათაური).

### 1.5 ფერი და თემა
- მხოლოდ ტოკენები. პროგრესი და აქტიური მდგომარეობა `--action`; მწვანე მხოლოდ დასრულებული/წარმატებული მდგომარეობისთვის; წითელი — შეცდომა და დესტრუქციული მოქმედება; ტოსტის ხატულა ტონს ემთხვევა (შეცდომა ✓-ით არასდროს).
- ყველა მარშრუტი ერთ თემაშია, 404-იც (`global-not-found` იღებს `layout`-ის html/body კლასებს და შრიფტებს).
- გრადიენტი არ გამოიყენება; ლურჯ თემაში არჩეული ჩიპი ლურჯია, არა შავი.

### 1.6 მობილური (390 და 360)
- ქვედა მოქმედების ზოლი viewport-ს ეკვრის: ზოლის წინაპარს `transform`/`filter` არ რჩება (`.ma-page` ანიმაცია `backwards` ან მხოლოდ opacity).
- გადასვლა: skeleton-ის სიმაღლე შინაარსის სიმაღლეს ემთხვევა (CLS ≈ 0), „უკან“ scroll-პოზიციას აბრუნებს, ანიმაცია 150–250ms ერთი easing-ით `ui/`-ში, `prefers-reduced-motion` პატივცემულია.
- Sheet/Modal: 390-ზე ქვედა ფურცელი handle-ით, `env(safe-area-inset-bottom)`, ღილაკები სრულ სიგანეზე primary ზემოთ, Escape/ფოკუსის დაბრუნება.
- ჰორიზონტალური ჩანართების/ფილტრების ზოლი ეკრანს არ სცდება მინიშნების გარეშე: `mask-image` ან wrap.
- ფორმაში კლავიატურის გახსნისას submit ღილაკი ხილული რჩება; ტოსტი ქვედა CTA-ს არ ფარავს.
- ქვედა ზოლში ≤2 ღილაკი + ხატულა „უკან“; სიტყვა შუაში არ იყოფა (`hyphens: manual`, `overflow-wrap: normal` ფაქტებში).

### 1.7 ადმინი
- ყველა ერთეული (მომხმარებელი, კომპანია + დოკუმენტები, მოთხოვნა, შეთავაზება, გარიგება + პრობლემა, შეფასება, საჩივარი, კონტენტი) იმართება ერთი ნიმუშით: სია ძიებით/ფილტრით → დეტალი → მოქმედება მიზეზით → ჩანაწერი audit-ში.
- MVP-ში ზედმეტი განყოფილებები (ხილვადობის პაკეტები, სადემო გზამკვლევი) ნავიგაციიდან იმალება.
- ცხრილის უჯრაში სიტყვა არ იჭრება; გრძელი განმარტება ერთხელ ჩანს (სათაურში/tooltip-ში), არა ყოველ რიგში.
