იმუშავე როგორც გამოცდილი პროდუქტის დიზაინერი და frontend ინჟინერი. შეამოწმე მთელი MeetAny რეალურ ბრაუზერში, აღმოაჩინე დიზაინისა და გამოყენების პრობლემების მიზეზები, გაასწორე ისინი კოდში და გადაამოწმე შედეგი. მიზანია გასაგები, კომფორტული ინფორმაცია და თანმიმდევრული განლაგება; მხოლოდ გვერდის ზომის შემცირება ან padding-ის ყველგან გაზრდა გამოსავალი არ არის.

მფლობელის მოთხოვნები
• იმუშავე მხოლოდ ლოკალურად. არ გამოაქვეყნო, არ შეცვალო production პარამეტრები ან ბაზის მონაცემები.
• შეინარჩუნე ფერადი ლოგო, შავი ძირითადი ღილაკები, მწვანე აქცენტები და შეცდომების/წარმატების მნიშვნელობის მქონე ფერები. ლურჯი UI თემა აღარ გამოიყენო.
• შეინარჩუნე მთავარზე კარუსელი. მოთხოვნის ატვირთული ფოტო უპირატესია; მისი არქონისას გამოიყენე თემატური ფოტო, მკაფიოდ როგორც კატეგორიის ილუსტრაცია. სხვისი პროდუქტი არ მიაწერო მოთხოვნის ავტორს.
• ფუნქციური წესები უცვლელია, მათ შორის მაქსიმუმ 15 პროდუქტი და კონტაქტის წვდომის წესები.
• არ გადაფარო უკვე შესრულებული ცვლილებები და არ შეცვალო მომხმარებლის სხვა სამუშაო.

დაფარვა
შეადგინე route × role × state სია: სტუმარი, მყიდველი, კომპანია, ადმინისტრატორი; მთავარი, როგორ მუშაობს, წესები, იდეები, კატალოგები, დეტალები, მოთხოვნის შექმნის ყველა ნაბიჯი, შეთავაზება, შედარება, გარიგება, ავტორიზაცია/რეგისტრაცია, კომპანიის დამატება/ვერიფიკაცია, ანგარიშის ყველა ჩანართი, შეტყობინებები/ჩატი, ადმინისტრირება, შეცდომა/ცარიელი შედეგი/ჩატვირთვა. მიუთითე რომელი მდგომარეობა შემოწმდა რეალური მონაცემით და რომელი — მხოლოდ უსაფრთხო ლოკალური UI სცენარით.

ვიზუალური აუდიტი
1. შეამოწმე 1440, 1024, 768, 390 და 320px სიგანეები. მთავარი ფუნქციები შეამოწმე კლავიატურით და შემცირებული მოძრაობითაც.
2. გაარჩიე ინფორმაციის დონეები: გვერდი → სექცია → ბარათი → სათაური/ტექსტი → მეტა → მოქმედება. სხვადასხვა ჯგუფებს შორის მეტი სივრცე უნდა იყოს, ვიდრე ერთ ჯგუფში.
3. იპოვე მიჭყლეტილი სათაური/აღწერა, მოკლე line-height, ზედმეტი ჩარჩოები და ერთმანეთზე მიბმული ქმედებები. ტექსტი არ გააპატარავო იმისთვის, რომ ცუდ ბადეში ჩაეტიოს.
4. გაზომე შიდა padding, ჯგუფებისა და სექციების gap, ტექსტის სიგანე, სვეტების მინიმალური სივრცე და ჰედერთან გასწორება. მოაშორე ურთიერთგამომრიცხავი CSS override-ები; დაარეგულირე მიზეზი საერთო ტოკენით ან კომპონენტის შესაბამისი წესით.
5. შეამოწმე გრძელი ქართული სახელები, მრავალხაზიანი მისამართები, ჩიპები, დიდრიცხვიანი მეტრიკები, სქროლვადი ცხრილები, sticky პანელები და ქვედა მოქმედებები. არ დაუშვა ტექსტის ერთმანეთზე დადება, ჰორიზონტალური გადაცდენა ან მოქმედების დაფარვა.
6. ფართო ეკრანზე გამოიყენე სივრცე გააზრებულად; არ დატოვო დიდი ცარიელი მხარე და პარალელურად ვიწრო ტექსტის სვეტი. მობილურზე დროულად გადადი ერთ სვეტზე და დატოვე შეხებისთვის საკმარისი ადგილი.
7. თითო ეკრანზე მთავარი მოქმედება მკაფიო იყოს. დამატებითი ინფორმაცია არ ეჯიბრებოდეს სათაურსა და მთავარ მოქმედებას. სტატუსები მხოლოდ ფერით არ გადმოსცე.
8. გადაამოწმე მენიუ, dropdown, dialog, ქვედა ფურცელი: ფოკუსი, დახურვა, კლავიატურა, ვალიდაცია და viewport-ში დარჩენა.

რეგისტრაციის ცალკე ღრმა ანალიზი
• ჩამოწერე არსებული ორი გზა: პირადი ანგარიში და კომპანია; თითოეული ეკრანი, სავალდებულო ველი, დამატებითი ველი, შექმნის მომენტი და შემდგომი გადასვლა.
• შეადარე „ჯერ პირადი პროფილი, შემდეგ კომპანიის დამატება“ მოდელს. შეაფასე როგორც კომპანიის მფლობელის, ისე მხოლოდ მყიდველის სამუშაო.
• იპოვე განმეორებული სახელი, ტელეფონი, ელფოსტა, კომპანიის სახელწოდება, ტიპი, სფერო, ქალაქი, პროდუქტები და დოკუმენტები. გაარჩიე პირადი იდენტობა და კომპანიის საჯარო/იურიდიული ინფორმაცია.
• თითოეული ველისთვის ახსენი რატომ სჭირდება ამ ეტაპს; არასაჭირო ინფორმაცია გადაიტანე შესაფერის შემდგომ ნაბიჯზე, დაკარგვის ან ახალი დუბლირებული წყაროს შექმნის გარეშე.
• შეამოწმე უკან დაბრუნება, შენახული მონაცემები, უკვე რეგისტრირებული მომხმარებლის კომპანიის დამატება, არასრული რეგისტრაციის გაგრძელება და სწორი CTA/მოლოდინი.
• არ დაამატო მრავალკომპანიანი როლები ან ახალი მონაცემთა მოდელი დამალულად. ასეთი ცვლილება გამოყავი რეკომენდაციად, მიზეზითა და ფარგლებით.

შესრულების წესი

საბოლოო შედეგი

დამატებითი კრიტერიუმი — ერთი მონაცემი ერთხელ

OTP პროვაიდერის სიმულაცია ცალკე აღრიცხეთ; აპლიკაციის API პასუხებით ნუ დაფარავთ შენახვის ხარვეზს.
