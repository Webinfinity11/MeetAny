# პარამეტრები — ერთი primary

2026-10-14 · კოდის commit: `0d7f351` · dev `3449` (`--webpack`), JWT fixture `4449`, ლოკალური ბაზა `meetany_layout_profile`.

ბლოკის „შენახვა“ სუფთა მდგომარეობაში secondary/disabled-ია, ცვლილებისას — primary. საერთო ზოლი მოიცავს ძირითად, აღწერის, მედიის, მისამართის, იურიდიულ და დისტრიბუციის ბლოკებს. `CompanyProducts.tsx`-ში მხოლოდ შენახვის ღილაკის ხაზი შეიცვალა, ორკესტრატორის დამატებითი მითითებით.

პაროლის „შეცვალეთ პაროლი“ ყოველთვის secondary-ა; CompanyUpgrade-ის ფუტერის „გააგრძელეთ“ — tint. დოკუმენტების „განხილვაზე გაგზავნა“ ანგარიშის `blockFooter` რეჟიმში secondary-ა: დოკუმენტები ატვირთვისას ინახება და ამ მოქმედებას dirty მდგომარეობა არ აქვს. enabled/submit/ვალიდაცია უცვლელია; onboarding-ზე მისი primary ვარიანტი შენარჩუნებულია.

დათვლა მთელ document-ში ხილულ `.ma-btn--primary` ელემენტებს მოიცავს, გლობალური ჰედერის გამოკლებით, დავალების შესაბამისად. ამ checkout-ში ჰედერის მოთხოვნის ღილაკი ჯერ primary-ა; მისი accent-ზე გადაყვანა პარალელური ნაკადის პასუხისმგებლობაა. კლიენტის ყველა `section` პარამეტრი არსებული ერთიანი პარამეტრების გვერდს აჩვენებს. რამდენიმე ერთდროულად შეცვლილ ბლოკზე თითოეული თავისი dirty მდგომარეობით ინიშნება, მიღებული გადაწყვეტილების შესაბამისად.

პაროლის უარყოფითი პასუხი ლოკალური auth fixture-ითაა იმიტირებული; რეალური Neon Auth და პაროლი არ იცვლება. დანარჩენი შენახვისა და ანგარიშის გაუმჯობესების RPC-ები ლოკალურ ბაზაზე რეალურად სრულდება. სკრიპტი `finally`-ში პროფილს, პროდუქტებსა და დისტრიბუციის მონაცემებს აღადგენს. axe მოწმდება ღილაკის ფერის CSS transition-ის დასრულების შემდეგ.
